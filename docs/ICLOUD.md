# Включение синхронизации через iCloud

Код синхронизации готов: SwiftData-модели с первого дня совместимы с CloudKit. Включение требует
платного Apple Developer Program ($99/год).

Данные хранятся в **личной базе iCloud каждого пользователя**: разработчику это ничего не стоит,
и вы не видите данные пользователей.

## Шаги

1. **Оплатите Apple Developer Program** и дождитесь активации.
2. **Укажите Team ID** в [project.yml](../project.yml), в `settings.base`:
   ```yaml
   DEVELOPMENT_TEAM: XXXXXXXXXX   # developer.apple.com → Membership → Team ID
   ```
3. **Сгенерируйте проект со всеми возможностями:**
   ```bash
   COIL_ICLOUD=true COIL_WIDGETS=true xcodegen
   open Coil.xcodeproj
   ```
   Так в приложение добавятся права на iCloud (CloudKit), App Group для виджетов, фоновые push-уведомления
   для синхронизации, и включится флаг компиляции `ICLOUD`.
4. **Зарегистрируйте контейнер.** В Xcode: таргет **Coil** → **Signing & Capabilities** → секция **iCloud**.
   Если контейнер `iCloud.com.maxouni.coil` подсвечен красным, нажмите «+» в списке контейнеров
   и создайте его с этим именем (или нажмите кнопку обновления). То же для **App Groups**:
   `group.com.maxouni.coil`.
5. **Проверьте на двух устройствах** с одним Apple ID: отметка на одном появляется на другом
   через несколько секунд или минут. В симуляторе синхронизация работает хуже; проверяйте на реальном iPhone.
6. **Перед релизом опубликуйте схему в Production.** Откройте [CloudKit Console](https://icloud.developer.apple.com)
   → контейнер `iCloud.com.maxouni.coil` → **Deploy Schema Changes…** → Deploy.
   Без этого шага в сборке из App Store синхронизация молча не работает, хотя при разработке всё было в порядке.

## Как это устроено

- [Persistence.swift](../Coil/Model/Persistence.swift): при флаге `ICLOUD` контейнер SwiftData создаётся
  с `cloudKitDatabase: .automatic`. Если iCloud настроен неправильно, приложение открывает ту же базу
  без синхронизации, и данные остаются доступны.
- Модели ([Habit.swift](../Coil/Model/Habit.swift)) следуют правилам CloudKit: у всех полей есть значения
  по умолчанию, нет уникальных ограничений, связи опциональные.
- Если одна и та же отметка была изменена на двух устройствах без связи, после синхронизации может появиться
  дубликат за день. Приложение берёт самую свежую запись (`updatedAt`), а при следующем изменении дня
  дубликаты удаляются.

## Правила для будущих изменений моделей

- Новые поля только со значениями по умолчанию или опциональные.
- Не переименовывать и не удалять поля после релиза: CloudKit-схема в Production только расширяется.
- После изменения моделей снова выполнить **Deploy Schema Changes** перед релизом.
